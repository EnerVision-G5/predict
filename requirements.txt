# L'ETL et l'entraînement vivent dans requirements-ml.txt, l'outillage de
# qualité dans requirements-dev.txt. Ce découpage n'est pas cosmétique : le
# job CI contract-drift n'installe que ce fichier, il n'a aucune raison de
# tirer pandas, xgboost, prophet et mlflow pour régénérer une spécification
# OpenAPI. Pour un poste de développement : pip install -r requirements-dev.txt
#
# NE PAS DÉ-ÉPINGLER SANS PR DE CONTRAT.
#
# fastapi et pydantic sont épinglés à la version exacte parce que ce sont eux
# qui génèrent la spécification OpenAPI. Une montée de version, même en patch,
# peut produire un JSON différent (ordre, titres générés, forme des anyOf,
# version d'OpenAPI émise) alors qu'aucun DTO n'a bougé. Le job CI
# contract-drift comparerait alors le code au contrat gelé et échouerait sur
# une dérive qui n'existe pas, et une régénération du contrat masquerait la
# vraie cause en la faisant passer pour une évolution métier.
#
# Pour monter fastapi ou pydantic : ouvrir une PR sur
# enervision/docs/contracts qui contient à la fois le bump de version ici et
# le contrat régénéré, et la faire relire par les trois consommateurs comme
# n'importe quelle évolution de contrat.
